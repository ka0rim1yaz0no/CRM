## Rollback

Original live source/build directories were not overwritten. Original process
definitions 0 (`crm`) and 6 (`crm-backend`) are retained stopped. A code rollback
uses the Node 22 PATH, stops the two new processes, restarts the two retained
processes, verifies API/login health, then saves the process list:

```sh
export PATH=/root/.nvm/versions/node/v22.22.2/bin:$PATH
pm2 stop crm-frontend-20261021
pm2 stop crm-backend-20261021
pm2 restart 6
pm2 restart 0
curl -fsS http://127.0.0.1:4000/api/health
pm2 save
```

No database restore belongs in a routine code rollback. Encrypted database
archives and their manifest are retained under
`/root/assistly-release-backups/crm-20261021-eb493d6`; encryption keys are retained
separately in the root-only backup-key directory. Never print a key or pass it on
a command line. A future restore requires a separately reviewed destination and
verification, preferably into an isolated database first.
